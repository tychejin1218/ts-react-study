# 실습 마무리(정리 후 커밋) 스킬

playground 등의 학습 실습 파일을 커밋하기 전에, 배운 내용을 되짚을 수 있도록 정리한 뒤 커밋한다.
대상 파일을 지정하면 그 파일을, 없으면 최근 변경된 학습 파일을 대상으로 한다.

## 정리 형식 (기준 파일: `playground/ts/day01-02-basics.ts`)

각 실습을 아래 구조로 묶는다.

1. **파일 최상단**: 한 줄 제목 + 실행 방법 주석 (예: `// 실행: npx tsx <파일> / 타입 검사만: npx tsc`)
2. **실습 단위 블록**: 각 실습마다 다음 순서의 주석 헤더를 붙인다
   - `// 실습 N: <개념 제목> — <한 줄 핵심>`
   - 무엇을 확인했는지 2~4줄 요약
   - `// → 정리: <그 실습의 결론 한 줄>`
   - 그 아래 실제 코드
3. **에러/예외를 내는 학습용 코드**: 지우지 말고 **주석 처리**한 뒤, 왜 문제인지(컴파일 에러인지 런타임 예외인지) 한 줄로 남긴다. 정상 실행되는 데모 코드는 살려둔다
4. 짧은 변수명이 파일 내에서 충돌하지 않도록 이름을 조정한다 (같은 스코프 중복 선언 방지)

## 진행 순서

1. **대상 파일 확인**: 인자로 받은 경로(없으면 `git status`로 최근 변경 학습 파일)를 읽는다
2. **정리**: 위 형식으로 재구성한다. 학습 흔적(시도한 코드, 함정 예제)은 주석으로 보존하되, 배운 결론을 `→ 정리:` 줄로 명시한다
3. **실행 확인**: `npx tsx <파일>`이 에러 없이 실행되고, `npx tsc`가 통과하는지 확인한다. 실패하면 원인을 고친 뒤 다시 확인한다
4. **커밋**: `commit` 스킬의 규칙(`<type>: <description>`, Co-Authored-By 미포함)을 따른다. 정리 커밋은 보통 `docs` 또는 `chore` 타입. 커밋 메시지 초안을 보여주고 확인받은 뒤 커밋한다

## 핵심 규칙

- **학습 맥락을 지우지 않는다.** 정리는 "깔끔하게 지우기"가 아니라 "나중에 다시 봐도 복원되게 남기기"다
- 커밋 전 반드시 실행/타입 검사를 통과시킨다 (깨진 파일을 커밋하지 않는다)
- 빌드 산출물(`.js`, `.d.ts`, 소스맵 등)은 커밋에 포함하지 않는다
